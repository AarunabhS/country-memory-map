# Contributing

Before making a material change, read [`AGENTS.md`](AGENTS.md) for repository policy, [`ARCHITECTURE.md`](ARCHITECTURE.md) for verified boundaries and known defects, and [`docs/DEVELOPMENT_PROTOCOL.md`](docs/DEVELOPMENT_PROTOCOL.md) for the required impact assessment and workflow. Use [`docs/QA_MATRIX.md`](docs/QA_MATRIX.md) to select and record applicable automated and manual checks.

Keep pull requests narrow and preserve protected behavior unless the change explicitly authorizes it. Complete the pull-request template with scope, affected systems, exact test results, manual evidence or outstanding verification, known limitations, rollback, and any architecture decision. Never claim browser, accessibility, deployment, or production verification that was not performed.
