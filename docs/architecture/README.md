# Architecture decision records

Use an ADR for a durable choice that affects shared architecture, data/persistence, routing, map/globe core, multiplayer core, design-system/GameShell contracts, deployment, security, or a major dependency.

1. Copy [`ADR-template.md`](ADR-template.md) to `NNNN-short-title.md`.
2. Use status `Proposed` while alternatives are under review.
3. Change to `Accepted`, `Rejected`, `Superseded`, or `Deprecated` only when that action actually occurs.
4. Link the task/plan and later ADRs that supersede it. Do not rewrite accepted history; add a new ADR.
5. Separate current evidence, proposed target, approved work, and production verification.

No historical ADRs were created by Governance v1 because the repository did not contain contemporaneous records proving those decisions. Candidates are listed in `../CHANGELOG_DECISIONS.md`.
